# VPN-бот: ручная оплата → авто-выдача ключа 3x-ui

Telegram-бот на aiogram 3: пользователь выбирает тариф (включая бесплатный
пробный период на 2 дня) и способ оплаты → переводит деньги вручную
(ЮMoney / Ozon Банк — настраивается) → нажимает «Я оплатил» →
администратор подтверждает оплату кнопкой в чате с ботом → бот сам
создаёт/продлевает клиента **во всех текущих инбаундах** вашей 3x-ui
панели и присылает персональную подписочную ссылку и инструкцию по
подключению.

Никакого эквайринга/банковской интеграции в проекте нет — ни платёжного
шлюза, ни вебхука. Домен с HTTPS нужен только если захотите единую ссылку
вместо нескольких (см. раздел «Единая подписка»), для приёма платежей он
не требуется в принципе.

## Как это устроено

```
Telegram-бот (aiogram, long polling)
        │  пользователь выбирает тариф (или бесплатный пробный период)
        ▼
Бот показывает реквизиты + код заказа, пользователь переводит деньги сам
        │  жмёт «Я оплатил» (для пробного периода этот шаг пропускается)
        ▼
Админу приходит уведомление с кнопками ✅ Подтвердить / ❌ Отклонить
        │  админ вручную сверяет перевод по коду/сумме в своём банке
        ▼
services/provisioning.py
        │  получает АКТУАЛЬНЫЙ список всех инбаундов через API (panel/xui_client.py, py3xui)
        │  создаёт/продлевает клиента во всех них с одним uuid, но СВОИМ subId
        │  на каждый инбаунд (см. примечание ниже)
        │  пишет подписку и платёж в БД (SQLite/Postgres)
        ▼
Бот шлёт пользователю ссылку(и)-подписку + инструкцию
        │  несколько нативных ссылок ПО УМОЛЧАНИЮ, или одна через
        │  sub_server.py, если настроен PUBLIC_SUB_BASE_URL (см. ниже)

services/billing_scheduler.py (APScheduler, раз в 6 часов)
        │  за ~2 дня до истечения любой подписки (обычной или пробной)
        │  шлёт пользователю напоминание продлить вручную
```

Поскольку список инбаундов запрашивается заново при каждой выдаче/продлении
ключа, **новые инбаунды, добавленные в панели, автоматически подключаются**
и новым, и существующим клиентам при следующем продлении — ничего в коде
редактировать не нужно.

## Структура проекта

```
config.py               # настройки из .env
plans.py                 # тарифы (включая пробный период) — правите под себя
payment_methods.py       # способы ручной оплаты (ЮMoney/Ozon Банк) — из .env
db/models.py, database.py
panel/xui_client.py      # обёртка над py3xui: провижининг во ВСЕ инбаунды, продление
sub_server.py            # опционально: агрегатор единой подписки (см. ниже)
bot/handlers.py, keyboards.py, texts.py
services/provisioning.py       # что делать при подтверждённой оплате / активации триала
services/billing_scheduler.py  # напоминания об истечении подписки
main.py                  # точка входа
tests/                    # smoke-тесты на моках (без реальных 3x-ui/Telegram)
```

## Установка

Требуется Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Дальше заполните `.env` — по пунктам ниже.

### 1. Telegram

- `BOT_TOKEN` — получаете у [@BotFather](https://t.me/BotFather)
- `BOT_USERNAME` — username бота без `@`
- `ADMIN_IDS` — ваш tg id (например, от [@userinfobot](https://t.me/userinfobot)),
  через запятую если админов несколько — сюда приходят заявки на оплату и алерты
- `BOT_PROXY_URL` — если `api.telegram.org` недоступен напрямую (блокировка
  провайдера/DPI: `ping` до Telegram проходит, а TCP:443 — нет). Укажите
  рабочий SOCKS5/HTTP-прокси, например `socks5://user:pass@host:port`

### 2. 3x-ui

- `XUI_HOST` — адрес панели вместе с секретным путём, например
  `https://your-server:2053/AbCdEfGhIj`
- `XUI_USERNAME` / `XUI_PASSWORD` — логин/пароль панели. Если включена
  авторизация по токену (Settings → API Token) — используйте `XUI_TOKEN`
  вместо логина/пароля
- Если в панели включена 2FA (Settings → Access → Two-Factor Authentication) —
  впишите в `XUI_TOTP_SECRET` base32-секрет, показанный под QR-кодом при
  включении 2FA (не 6-значный код из приложения, а именно секрет)

**Инбаунды указывать нигде не нужно** — бот сам запрашивает актуальный
список через API при каждой выдаче/продлении ключа и подключает клиента
ко всем сразу.

**Подписочный сервис** (без него не будет единой ссылки-подписки): в
панели → Settings → Subscription Settings — включите его и запишите в
`.env`: `SUB_DOMAIN`, `SUB_PORT`, `SUB_PATH` (обычно `/sub/`), `SUB_TLS`.
Итоговая ссылка: `https://{SUB_DOMAIN}:{SUB_PORT}{SUB_PATH}{sub_id}`.

**Если инбаундов несколько:** начиная с 3x-ui v3.2.5 панель требует, чтобы
`subId` был уникален для всей панели (раньше можно было дать один subId
клиентам в разных инбаундах, чтобы получить одну общую ссылку на всё —
теперь это прямо запрещено, и в самой панели нет и не было UI для
привязки одного клиента сразу к нескольким инбаундам — проверено по
исходникам фронтенда). Поэтому у каждого инбаунда СВОЙ subId и своя
нативная ссылка-подписка. По умолчанию бот присылает их все списком, с
подписью по `remark` инбаунда. Если хотите вместо этого ОДНУ ссылку —
см. раздел «Единая подписка» ниже. Если инбаунд всего один — разницы нет,
пользователь и так получит ровно одну ссылку.

**Убрать "34D,4H⏳" (оставшееся время) из названия сервера в клиенте** — это
настройка самой панели, не бота: там же, в Settings → Subscription,
выключите переключатель показа доп. информации (в разных версиях/языках
панели может называться "Show Info" или похоже) — время и трафик перестанут
дописываться в название конфига.

### 3. Единая подписка на все инбаунды (опционально)

Раз панель больше не даёт объединить несколько инбаундов в одну ссылку
нативно, бот может сделать это сам: `sub_server.py` — небольшой HTTP-сервер,
который по запросу забирает уже готовые (полностью корректные, со всеми
Reality/TLS-параметрами) конфиги с каждого нативного `/sub/...` и
склеивает их в один base64-блок — ровно то, что ожидает Happ/v2rayNG/etc
от обычной подписки.

Без настройки этого раздела бот присылает несколько ссылок (по одной на
инбаунд) — это тоже полностью рабочий вариант, просто менее удобный, если
инбаундов много. Чтобы включить единую ссылку:

1. Нужен домен с HTTPS, направленный на ваш сервер (тот же, что описан в
   разделе про systemd/nginx ниже — если делали его раньше для ЮKassa,
   просто переиспользуйте).
2. Добавьте в nginx-конфиг ещё один `location`:
   ```nginx
   location /mysub/ {
       proxy_pass http://127.0.0.1:8081/;
   }
   ```
   (обратите внимание на слэш в конце обоих путей — так nginx срежет
   `/mysub/` из запроса перед проксированием)
3. `sudo nginx -t && sudo systemctl reload nginx`
4. В `.env`:
   ```
   PUBLIC_SUB_BASE_URL=https://ваш-домен.ru/mysub
   ```
5. Перезапустите бота — `sub_server.py` сам поднимется на порту
   `SUB_SERVER_PORT` (по умолчанию 8081, слушает только `127.0.0.1`,
   наружу не торчит) и дальше бот будет присылать одну ссылку вида
   `https://ваш-домен.ru/mysub/<токен>` вместо списка.

Токен генерируется один раз при первой покупке/активации триала и не
меняется при продлении — ссылку не нужно перевыдавать пользователю.

**Название профиля в клиенте (Happ и т.п.):** без специального заголовка
такие клиенты обычно показывают в списке подписок просто домен вместо
осмысленного имени. Сервер сам добавляет заголовок `Profile-Title` со
значением `BRAND_NAME` из `.env` (по умолчанию "My VPN" — задайте своё) —
именно это увидит пользователь как название профиля. Также агрегирует
суммарный расход трафика по всем инбаундам в заголовок
`Subscription-Userinfo`, чтобы клиент показывал реальный остаток, а не
пустоту, плюс `Profile-Update-Interval` (`SUB_UPDATE_INTERVAL_HOURS`,
по умолчанию 12) — как часто клиент сам обновляет список серверов.

### 4. Способы оплаты (ЮMoney / Ozon Банк)

- `PAYMENT_RECIPIENT_NAME` — ваше ФИО, показывается рядом с реквизитами
- `YOOMONEY_WALLET` — номер кошелька ЮMoney
- `OZON_REQUISITE` — номер карты Ozon Банк или телефон для перевода

Заполните хотя бы один — соответствующая кнопка появится в боте
автоматически, оба сразу не обязательны.

Как это работает: пользователь переводит деньги сам по показанным
реквизитам, жмёт «Я оплатил» → всем из `ADMIN_IDS` приходит уведомление с
кодом заказа и кнопками ✅/❌ → сверяете перевод в своём банковском
приложении по сумме и коду в комментарии → жмёте «Подтвердить» → бот сам
выдаёт ключ.

### 5. Пробный период

- `TRIAL_ENABLED` — `true`/`false`, включить бесплатный пробный тариф
- `TRIAL_DURATION_DAYS` — сколько дней длится (по умолчанию 2)

Доступен один раз на пользователя (отслеживается флагом в БД). При выборе
пробного тарифа шаг с реквизитами/подтверждением админом пропускается —
ключ выдаётся сразу.

### 6. Админ-панель (через бота, без захода в 3x-ui)

Команда `/admin <tg_id>` (доступна только `ADMIN_IDS`, для остальных бот
молчит, будто команды не существует) показывает карточку пользователя:
тариф, статус, срок действия, расход трафика, число подключённых
инбаундов — и три кнопки:

- **➕7 дн. / ➕30 дн.** — продлить подписку вручную (например, если оплата
  прошла нестандартным способом или в качестве бонуса), без создания
  повторной заявки на оплату
- **🚫 Отключить / ✅ Включить** — мгновенно выключает клиента во всех его
  инбаундах в панели (доступ пропадает физически, не только в БД бота) и
  включает обратно
- **🔄 Пересинхронизировать** — досоздаёт клиента в инбаундах, которые
  появились в панели уже после того, как пользователь купил подписку, не
  дожидаясь его следующего продления

Узнать tg_id пользователя: он есть в каждом уведомлении о заявке на оплату
(«Пользователь: @username») — либо попросите пользователя переслать вам
любое сообщение от [@userinfobot](https://t.me/userinfobot).

## Тарифы

Правьте `plans.py`: цена, срок, лимит трафика (`total_gb`, 0 = безлимит),
лимит одновременных подключений (`limit_ip`). Инбаунды указывать не нужно —
подключаются все текущие автоматически (см. раздел про 3x-ui выше).

## Запуск

Локально/для теста:
```bash
python main.py
```

### Продакшн: systemd

`/etc/systemd/system/vpnbot.service`:
```ini
[Unit]
Description=VPN Telegram bot
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/vpn_bot
EnvironmentFile=/opt/vpn_bot/.env
ExecStart=/opt/vpn_bot/.venv/bin/python main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**Важно:** в `.env` через `EnvironmentFile=` нельзя оставлять комментарии
в конце строки того же значения (`KEY=value # комментарий`) — systemd не
умеет их обрезать, в отличие от обычного запуска `python main.py`. Держите
строки в `.env` строго `КЛЮЧ=значение`, без хвостов после значения.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vpnbot
sudo journalctl -u vpnbot -f    # логи в реальном времени
```

После правок кода: `sudo systemctl restart vpnbot`.

Домен, nginx и HTTPS **не обязательны** для самой оплаты и выдачи ключей —
только если захотите единую ссылку-подписку вместо нескольких (раздел
«Единая подписка» выше).

## Известные упрощения — что доделать перед полноценным продакшном

- Один пользователь = одна подписка (при покупке другого тарифа старая
  продлевается/переключается, а не создаётся вторая).
- Нет админ-панели (посмотреть/отключить/продлить пользователя руками) —
  сейчас это ручные операции через 3x-ui панель напрямую или через
  `panel.xui_client.disable_client(tg_id)` из python-консоли.
- Нет миграций схемы БД (Alembic) — таблицы создаются как есть при старте;
  при изменении моделей на проде нужно будет удалить и пересоздать `bot.db`
  (если это уже боевая база с подписчиками — писать миграцию вручную).
- Логи только в stdout — journald через systemd даёт базовый уровень,
  этого может хватить для старта.
